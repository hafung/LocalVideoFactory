# 输入文案，自动找素材、配音、剪成片：我做了一个本地 AI 短视频工厂

写完一段文案，离发出一条视频还有多远？

通常还得录音或生成配音，找视频素材，把画面剪到合适的位置，对字幕，再调一遍音乐和人声音量。每一步都有工具，但把它们接起来，仍然要花不少时间。

我做了一个开源项目 **LocalVideoFactory**，想把这些事情串成一条可以在自己电脑上运行的生产线：**输入文案，自动配音、搜索素材、对齐字幕并剪辑成片。**

有原视频，可以让它按内容挑片段；没有原视频，也可以从素材开始组织画面。核心 AI 在本机 CPU 上运行，无需独立显卡。

项目地址：[github.com/hafung/LocalVideoFactory](https://github.com/hafung/LocalVideoFactory)

## 从“我有文案”到“我有一条视频”

使用时，最少只需要提供文案。

应用会先理解文案、规划分镜，为每一段旁白确定要找什么画面，再生成配音。配音完成后，用实际声音的长度安排时间轴，对齐字幕和画面。

这一步很实用。说同样一句话，不同音色、不同停顿，长度可能不一样。先得到真实旁白，再编排画面，就有了统一的时间依据。

接着，它会从原片、本地素材库和在线素材里选择画面，补齐整条时间轴，生成可以预览和导出的成片。

可以把流程理解成：

**文案 → 分镜 → 配音 → 字幕对齐 → 选片与补素材 → 剪辑合成 → 预览精修。**

## 自动找素材，也会从你的原片里挑片段

这是我最希望讲清楚的部分。

如果你提供了原视频，应用会结合抽帧画面、原片语音、镜头和动作边界，寻找与旁白内容相符的片段。例如，旁白讲到某个产品的使用过程，就尝试从原片里找到对应的展示或操作画面。

这里常说的“多模态”，落到使用体验上，就是**结合画面和声音理解原片，再帮你挑片段**。

原视频比旁白长，就从中挑选需要的内容；比旁白短，或有些段落找不到合适画面，就补充其他素材。原片不会为了凑时长被自动慢放或机械循环，同一原片时间区间也不会反复使用。

补画面时，应用优先使用本地视频，再通过 Pexels 搜索和下载在线视频。视频不足时，可以使用短时图片；剩余空缺由动态文字补齐。没有提供原片，也会走这套素材组织流程。

因此，它已经把按旁白选片、裁切、排列和补画面连在了一起，也就是自动 B-roll 剪辑的基础流程。实际选片效果仍然取决于模型理解和可用素材，生成后可以继续调整。

## 生成之后，还能按分镜精修

自动生成解决了起稿的问题，最终呈现仍然需要创作者把关。

LocalVideoFactory 把分镜做成卡片。预览后发现某个画面不合适，可以直接更换这一段，查看候选素材，或者选择同一视频的其他区间。相邻几句话也可以合并，共用一个画面。

![创作工作台：文案、成片预览与分镜卡片](../screenshots/studio.png)

字幕支持按词或短语高亮，也能手动调整分组。只改字幕时，可以复用已有旁白。

声音部分支持本地配音和声音克隆，旁白、原声、BGM 可以分别调整音量，旁白出现时还能自动压低背景声音。音乐通过 Openverse 检索，可以试听、下载并选作配乐，默认筛选 CC0，来源和许可信息会随素材保存。

最后可以导出 MP4，也能单独导出 MP3 音轨、SRT 和 ASS 字幕，方便继续创作。

## 核心 AI 在自己的 CPU 上运行

文案分镜和原片理解使用 Qwen3.5，配音与音色克隆使用 Qwen3-TTS，语音识别和字幕对齐使用 SenseVoice，最后由 HyperFrames 与 FFmpeg 完成渲染和合成。

这些核心 AI 能力在本机运行，支持 CPU 推理，无需独立显卡。模型和本地素材准备好后，可以离线完成核心创作流程；使用 Pexels 或 Openverse 搜索素材时，需要联网，搜索词会发送给对应服务。

CPU 能运行，也意味着需要给模型留出处理时间。生成耗时和内存占用会随模型、文案和原片长度变化。目前桌面运行与打包主要面向 Windows x64，具体准备方式见[构建与运行指南](../building.md)。

## 一个人，也能拥有自己的短视频生产线

我希望 LocalVideoFactory 能帮创作者省下配音、找素材、对字幕和初步剪辑的重复劳动，让一段写好的文案更容易变成可以观看、可以修改的作品。

如果你在做产品介绍、知识讲解、观点口播，或者只是想把一个有趣的想法做成短视频，欢迎试用，也欢迎带着实际素材来提反馈。
